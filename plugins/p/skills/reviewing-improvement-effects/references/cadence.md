# Choose the next diagnostic

These are review prompts, not a scheduler or a requirement to run every skill.
Start with the pilot's recorded trigger; use periodic checks only when useful.

| Question or trigger | Existing skill | Evidence to carry forward |
|---|---|---|
| Weekly or recurring annoyance across work | `finding-friction-in-recent-sessions` | Source-specific candidates, denominators, redacted examples, and successes for comparison |
| Monthly, growing standing instructions, or a rule that appears ineffective | `auditing-workflow-rules-against-behavior` | Applicable opportunities, historical versions, observed adherence or insufficient evidence |
| Work was announced but apparently stopped | `counting-stopped-promises` | Supported-source terminal turns and continuation; unsupported input is not zero |
| Response format changed or became burdensome | `maintaining-the-format-plugin` | Mechanical health separately from interim/final behavior and user value |
| Substantive implementation ready for review | `adequacy-review` | Canonical blinded review findings and resolved defects; review completion is not adoption |
| Delegation was rejected, repeated, or unusable | `auditing-agent-contracts` | Effective brief, scope, inputs, return, and actual parent use |
| Named friction survives local instruction or skill fixes | `scouting-tools-for-open-frictions` | Concrete unmet need and a bounded replacement experiment |
| Pilot reaches its date/task trigger or a regression appears | `reviewing-improvement-effects` | Matched baseline/follow-up evidence and a disposition with its next owner |

For a new pilot, collect a bounded baseline before activation when possible.
At activation, preserve the exact version and observed exposure. At the trigger,
include ordinary completed work, failures, and later consumption. If the owner
has no observation for adoption or value, record unknown and request that precise
observation only when it is necessary to decide the pilot. Do not substitute
dispatch counts, skill invocation counts, or lower token use for user benefit.
