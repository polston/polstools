# retro — four measurement fixes

**Status:** spec, one review round folded (2026-08-18)
**Home:** `plugins/retro/` in polstools
**Extends** `2026-08-12-retro-design.md`, whose "Open" section named three of
the four areas below. Fix 4 is new scope, added after the review round.

## Why

Four defects, measured against the live corpus on 2026-08-18 and re-measured by
review. Every number here is a fresh measurement, not a recollection: an earlier
draft of this spec quoted 11,619 prompts and 1,335 corrections, and both were
wrong — they came from a hand-written scan that accumulated the prior-assistant
length instead of replacing it, and that counted interrupt records as prompts.

| # | Defect | Measured |
|---|---|---|
| 1 | Files reported "unreadable" are not transcripts | 22 of 1,900; all workflow journals; 0 genuine read failures |
| 2 | Per-session rates divide one population by another | printed 28.8 prompts/session against a true 9.5 |
| 3 | Only one fixed transcript directory can be measured | window starts 2026-06-20; older transcripts exist elsewhere, compressed |
| 4 | 78% of the corpus is never examined | 1,481 subagent transcripts; 12% return nothing at all |

### What review killed, and what replaced it

The draft claimed the ledger was polluted by tool-generated turns — 6,049 of
11,619 counted prompts — and that this made workflow-heavy sessions rank as
high-friction. The first half is real; the consequence was wrong.

Measured: **all** 6,049 marked records sit in subagent transcripts. Main-session
transcripts contain **zero**. `cmd_pack` already excludes subagent rows from
ranking and from `moments`, so none of that text ever reached a score. Applying
the exclusion changes 5 of 424 session rows' scores and leaves the top-20
ranking identical in order. Corrections drop by 1, from 979 to 978.

The defect that does distort what you read is next to it: `totals()` sums every
counter over **all** rows including subagent transcripts, then `cmd_pack`
divides by a session count that **excludes** them. Two populations, one ratio.
That is fix 2 now.

A second finding reorders the work. By actual contribution to `friction_score`
across the corpus: `tool_retries` **54%**, `correction_turns` 29%, tool errors
10%, interrupts 6%, permission-mode changes 2%. The crudest heuristic in the
tool — same tool name and argument shape twice in a session is a "retry" — is
also the dominant input to the ranking. It, not corrections, is the metric most
worth validating.

## Fix 1 — separate "not a transcript" from "unreadable"

`measure()` returns `None` both for a file that could not be read and for a file
that read fine and holds no conversation. `extract` prints both as `unreadable`.

Three outcomes, reported separately, detected by structure rather than filename
so the next sidecar format the CLI introduces is handled too:

- **measured** — produced a row
- **not a transcript** — read fine, zero records of type `user` or `assistant`
- **unreadable** — could not be opened or decoded

Constraints the current code imposes:

1. `extract` already prints unchanged files under the name `skipped`. The new
   outcome needs a different word in both the code and the output line.
2. `read_records` swallows `OSError` and yields nothing, which is what makes the
   two conditions indistinguishable. It must signal failure to its caller.
   Failures also occur mid-iteration, not only at open.
3. `moments()` is the second caller of `read_records`. Whatever signalling is
   chosen, a pack run must not die because one file went unreadable.
4. `cmd_extract` writes a fingerprint into the state file for failed files too,
   so a file that fails once is never retried until it changes. A transiently
   locked live transcript is dropped permanently. Failures must not be
   fingerprinted.
5. Files whose `stat()` fails currently fall into no bucket, so the printed
   counts do not sum. They belong in `unreadable`.
6. `cmd_extract` returns `None` and therefore always exits 0. Under the repo's
   convention a nonzero unreadable count is a flag: exit 1.

**Done when:** a `--rebuild` run reports 0 unreadable and 22 not-transcripts,
the counts sum to the file total, and a run with one deliberately unreadable
file exits 1 and retries that file on the next run.

## Fix 2 — one population per ratio

### 2a. `totals()` must not mix populations

Aggregate over an explicit population. `cmd_pack`'s per-session line divides
main-session counters by main-session count; subagent spend is reported as its
own line, not folded into a per-session rate.

No schema change, no rebuild, no re-measurement of anything on disk. Measured
effect on the whole ledger: prompts per session 28.8 → 9.5.

### 2b. Exclude tool-generated turns from human-turn counters

A user-role record carrying `sourceToolAssistantUUID` was generated by a tool,
not typed. The existing `toolUseResult is not None` guard misses 6,049 of them.
`user_prompts`, `correction_turns` and `interrupts` count only unmarked records.

State plainly what this buys, because it is not what the draft claimed: it makes
the **subagent** rows' counters honest (7,615 counted prompts there, 6,048 of
them machine text). Session ranking barely moves — 5 rows of 424, top-20 order
unchanged, corrections 979 → 978, interrupts 196 → 173. It costs a full
`--rebuild` and breaks trend comparability across the change.

Two limits on the marker, both measured, both stated so nobody over-trusts it:

- It is a precision instrument, not a complete one. 161 unmarked prompts still
  carry machine wrapper tags; the marker does not find them.
- On the archive corpus of fix 3, `sourceToolAssistantUUID` coincides exactly
  with `toolUseResult` across all 34 CLI versions present — marker-only records
  appear in 12 of the 27 live-corpus versions and none of the archive's. On
  older data this change is a no-op, and the ledger will show that as a step in
  the trend rather than a real behavioural shift.

### 2c. Split the correction signal

"Short reply after a long assistant turn" conflates three things:

| Turn | Meaning | Counter |
|---|---|---|
| "no", "stop", "revert", "instead" | friction | `correction_turns` |
| "yes", "sure", "go for it" | the process working | `approval_turns` |
| ends in `?` | a question | neither |

Precedence, which must be explicit or two implementers build different tools:
interrupt, then question, then approval, then correction. Questions and
approvals still count as `user_prompts` — they are prompts, just not friction.
`friction_score` weights `correction_turns` only; `approval_turns` is recorded,
not scored.

The rule lives in `classify_user_turn`, which `measure` and `moments` both call.
But `moments()` also carries its own record-level filter (`toolUseResult is
None`) and quotes any non-empty classification. It must apply the same marker
rule, and must not quote approvals as friction evidence.

### 2d. Validate the thresholds against hand labels

A `label` subcommand, covering `tool_retries` first — it is 54% of the score and
its rule is the crudest — and the turn classifier second.

1. Sample N turns the classifier fires on and N it does not, plus N candidate
   retries, with the preceding assistant turn for context, redacted.
2. Write them to a file under the work directory for the operator to mark.
3. Read the marked file back; report precision and recall per class, and sweep
   both thresholds.

Sample size 150 per side, seeded so a rerun samples the same turns. The sweep
needs the **unredacted** reply length and prior-assistant length stored as
numbers alongside each sample: `redact()` shortens text and the moment builder
truncates prior text to 300 characters, so a sweep over the stored text would be
measuring the wrong lengths.

**Done when:** the counters are populated, and precision and recall for the
settled thresholds are recorded in this document as aggregates.

## Fix 3 — additional transcript directories

- **Configuration:** a `RETRO_TRANSCRIPT_DIRS` environment variable, platform
  path-separator delimited, and an `extra_transcript_dirs` key in a config file
  under the work directory — which is `RETRO_HOME`-overridable, so the config
  must follow it rather than being hardcoded to the default location. Order:
  the default root first, then config file, then environment. No path is ever
  committed, documented by example, or named in a commit message.
- **Compressed input:** roots may hold `.jsonl.gz`. The file walk must widen
  beyond `*.jsonl`, and the `path.stem` fallback for a missing session id yields
  a name ending in `.jsonl` for those files — strip both suffixes.
- **Rows must carry their root.** `measure()` derives the ledger key *and*
  `is_subagent` from `path.relative_to(PROJECTS_DIR)`, falling back to the bare
  filename. For any foreign root that fallback silently drops the `subagents/`
  marker, so every archived subagent transcript counts as a session and deflates
  every per-session rate; and two files sharing a basename overwrite each other.
  The row records which root it came from, the key is (root, relative path), and
  `moments()` resolves through the root. Without this `moments()` fails silently
  — the rebuilt path does not exist, `is_file()` is false, and the pack quotes
  nothing rather than erroring.
- **Duplicate sessions across roots are not deduplicated.** The draft claimed
  they would be; the ledger key cannot do it, and session-id keying is the exact
  design the original ruled out after it collapsed 1,715 transcripts to 352. A
  composite key yields one row per file, and 10 session ids are known to appear
  in both the live corpus and the archive. `extract` reports the overlap count
  so it is visible rather than silent; removing it is out of scope.

**Done when:** with one extra root configured, `extract` measures its files with
`is_subagent` correct, `pack` quotes a moment from that root, the overlap count
is reported, and a run with no configuration produces byte-identical output to
today.

## Fix 4 — a subagent lens

Subagent transcripts are 1,481 of the corpus and are currently treated as spend:
excluded from ranking, excluded from moments, never read. Measured 2026-08-18,
they carry a distinct and recurring failure profile that nothing looks at.

| Signal | Measured | Is it a mistake? |
|---|---|---|
| Run produced no assistant text at all | 177 (12%) | Yes — dispatched, returned nothing |
| `StructuredOutput` rejected | 53 of 811 calls (6.5%), all schema/validation | Yes — the schema and the prompt disagree |
| Write refused on a precondition | 20 of 29 Write errors | Yes — wrote a file it had not read |
| Read on a path that does not exist | 26 of 80 Read errors | Yes — guessed a path |
| Runaway length | median 11 turns, p90 102, max 707 | Probably — nothing needs 707 turns |
| Non-zero exit from a command | 206 Bash, 63 PowerShell | **No** — a failing test is information |

The last row is the discipline this lens needs. An error rate is not a mistake
rate: `PowerShell` fails 18.1% of calls against `Bash` at 3.4%, but nearly all of
both are commands that ran and returned non-zero, which is frequently the
correct outcome. Only the categories above the line are counted as mistakes.

**What it adds:** per-transcript counters on subagent rows — returned nothing,
schema rejections, precondition failures, nonexistent-path reads, turn count —
and a `subagents` subcommand reporting them over a window, ranked by frequency.

**Why it is worth building:** each of those categories maps to an edit someone
can make — a dispatch instruction, a schema, a standing rule — and the same
counter then measures whether the edit worked. That is the loop the original
design exists to close, applied to the 78% of the corpus it currently ignores.

**Explicitly not in scope:** judging whether a subagent's *answer* was good. This
lens counts mechanical failures only. Quality needs labels, and labels are 2d's
problem.

## Invariants

1. **No other project is named**, in any file, doc, example, or commit message.
   Fix 3 ships a mechanism and nothing else.
2. The ledger contract holds: redefining a counter requires `extract --rebuild`
   before any trend over it means anything.
3. Message text leaves the tool in exactly two places — the `moments` section of
   a pack, and the labelling file — both through `redact()`. The module
   docstring says one place and must be updated with the change, not after it.
4. `redact()` does not catch another project's absolute paths — verified
   2026-08-18 on a synthetic path, which it returns unchanged. Packs therefore
   carry them. They stay in the work directory, are never committed, and are not
   safe to paste somewhere public without a read-through. Widening redaction to
   cover arbitrary foreign paths is out of scope here; knowing it does not is
   not.
5. The labelling file lives under the work directory and is never written inside
   a repository. `redact()` mirrors the mechanical categories of the privacy
   audit, which cannot recognise a project name; the labelling file therefore
   carries identifiers redaction will not catch.
6. Only aggregates from the labelling run go into this document, a commit
   message, or any other tracked file — never sample turns.
7. Stdlib only. No dependency, no build step, no daemon.

## Non-goals

No database, no daemon, no scheduler. No deduplication of sessions that appear
in two roots. No automatic threshold tuning — the operator sets them from the
labelled sample and they are written into the file as constants.
